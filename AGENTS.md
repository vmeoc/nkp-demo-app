# AGENTS.md

## Project
Flask "Hello ..." demo app. `app.py` serves `index.html` on port 8080 (override with `PORT`). Deployed to NKP via GitOps from `nkp-app.yaml`.

## Setup
- Python: use `.venv/bin/python` (venv is 3.9). App deps: `python3 -m pip install -r requirements.txt`. Contract/MCP tooling also needs `pip install pyyaml jsonschema` (not in requirements.txt).
- Node: `npm install` (v25 tested). MCP/UI build uses Vite.

## Run
- App: `.venv/bin/python app.py`, then http://localhost:8080.
- Docker: `docker build -t ... .` (image copies only `app.py` and `index.html`).

## Verify
- Python contract tests: `.venv/bin/python tests/test_contract_validation.py` (or `... -m unittest tests.test_contract_validation`).
  - Single test: `.venv/bin/python -m unittest tests.test_contract_validation.ContractValidationTests.test_prod_requires_cost_center`.
- MCP/UI smoke: `npm run test:mcp` (rebuilds `mcp-dist/` via Vite first).
- Render check: `.venv/bin/python .opencode/skills/nkp-deploy/render.py --check` (exit 2 if `k8s/base` is stale).
- Catalog / validate: `... render.py --print-catalog`; `... render.py --validate-input` (JSON contract on stdin).

## Architecture / boundaries
- Greeting text lives in `index.html` (`<h1>Hello ...</h1>`). Adding static assets requires updating the Dockerfile `COPY`.
- `k8s/base/*` is generated by `render.py` from `nkp-app.yaml`; never hand-edit.
- `k8s/kustomization.yaml` is CI-owned (image tag); never edit or regenerate.
- Correct skill path is `.opencode/skills/nkp-deploy/` (older docs/examples may still say `.github/skills/`).
- `mcp/` is the VS Code MCP validator/UI; `mcp/launch.mjs` runs `vite build` then the stdio server and reads `mcp-dist/mcp/contract-form.html`. `mcp-dist/` is a build artifact (gitignored).
- `.nkp/target.env` (gitignored) configures `check_deploy.sh`; copy from `.nkp/target.env.example`.

## NKP deploy flow
Follow `.opencode/skills/nkp-deploy/SKILL.md`. Summary:
1. Edit `nkp-app.yaml` at repo root only after explicit user approval.
2. Run `.venv/bin/python .opencode/skills/nkp-deploy/render.py` from repo root.
3. Optional preflight: `.opencode/skills/nkp-deploy/check_deploy.sh preflight` (needs kubectl + `.nkp/target.env`).
4. Commit only relevant files (never `git add -A`), `git pull --rebase`, `git push` on `main` (Flux watches main).
5. Verify: `.opencode/skills/nkp-deploy/check_deploy.sh verify`.
- CI workflow (`.github/workflows/build-deploy.yml`) ignores changes under `k8s/`, `nkp-app.yaml`, `.opencode/skills/`, and `**/*.md`, so contract-only changes do not rebuild the image.
- Do not change `app` in an existing deployment without warning (creates a new app). Do not commit secrets or force-push.

## Quirks
- `render.py` and MCP validation require `pyyaml` + `jsonschema`, which are not in `requirements.txt`.
- `render.py` uses paths relative to the current working directory; always run from repo root.
- Python venv is 3.9 while the Dockerfile targets 3.12; don't assume runtime parity.
- `expires` must be a future date; forbidden in prod; `cost_center` required in prod; tracing incompatible with `static` runtime.
